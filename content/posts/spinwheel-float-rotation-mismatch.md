## 🐛 문제 상황

이전 포스트에서 다룬 돌림판의 또 다른 버그입니다. 이번에는 재회전 없이 한 번만 돌려도 발생하는 문제입니다.

돌림판이 시각적으로는 "카페" 세그먼트에서 멈추는데, 결과 화면에는 "영화"가 표시되었습니다. 즉, 사용자가 보는 것과 실제 결과가 다른 상황이었습니다.

## 🐛 에러 메시지

에러 메시지는 없었습니다. 기능 버그로, 눈에 보이는 결과와 코드가 계산한 결과가 불일치하는 현상이었습니다.

## 🧭 시행착오

먼저 결과 인덱스 계산 로직(`Math.floor(finalAngle / segmentAngle)`)을 확인했습니다. 공식 자체는 맞았습니다.

다음으로 Canvas에 그려지는 세그먼트 위치와 결과 계산에 사용하는 세그먼트 위치가 일치하는지 비교했습니다. 이것도 같은 `segmentAngle` 값을 사용하고 있었습니다.

문제는 `extraRotation` — 돌림판이 빙글빙글 도는 "추가 회전량"에 있었습니다.

## 🔍 원인 분석

돌림판 애니메이션은 목표 세그먼트까지의 각도에 "추가 회전량"을 더해서 여러 바퀴를 돈 후 멈추는 방식입니다.

```typescript
// 문제 코드 — 비정수 배수
const extraRotation = (5 + Math.random() * 3) * Math.PI * 2;
```

`5 + Math.random() * 3`은 `5.0 ~ 8.0` 사이의 **소수를 포함하는 값**입니다. 예를 들어 `6.73`이 되면, 돌림판이 정확히 6.73바퀴를 추가로 돕니다.

문제는 0.73바퀴에 해당하는 잔여 각도입니다. 이 잔여 각도가 목표 세그먼트의 각도에 더해지면서, 최종 멈춤 위치가 의도한 세그먼트 중앙에서 벗어납니다. 세그먼트 크기가 작을수록(후보가 많을수록) 인접 세그먼트로 밀려나는 확률이 높아집니다.

Canvas 렌더링에서는 실제 각도 기반으로 그리기 때문에 시각적으로는 밀린 위치에서 멈추지만, 결과 인덱스 계산에서는 원래 의도한 인덱스를 사용하거나 — 혹은 그 반대로 — 시각적 위치와 계산 결과가 어긋나게 됩니다.

## 🛠️ 해결

`Math.floor()`로 정수 배수를 강제 적용했습니다. 정수 바퀴를 돌면 시작 각도와 끝 각도의 상대 위치가 정확히 일치합니다.

```typescript
// 수정 — 정수 배수 (5~8바퀴 중 하나)
const extraRotation = Math.floor(5 + Math.random() * 4) * Math.PI * 2;
```

`Math.floor(5 + Math.random() * 4)`는 `5, 6, 7, 8` 중 하나의 정수를 반환합니다. 정수 x `2π`이므로 추가 회전 후 각도 오프셋이 정확히 0이 됩니다.

## ✅ 핵심 정리

- 회전 애니메이션의 **추가 회전량은 반드시 `2π`의 정수 배수**로 설정해야 합니다. 소수가 포함되면 잔여 각도만큼 결과가 밀립니다.

- "눈에 보이는 것"과 "코드가 계산하는 것"이 다른 버그는 **중간 계산의 미세한 오차**에서 비롯되는 경우가 많습니다.

- 부동소수점 연산이 관여하는 로직에서는, 최종 결과에 영향을 주는 값이 **정수 또는 고정된 값**인지 확인해야 합니다.
